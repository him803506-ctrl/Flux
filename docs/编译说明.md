# Flux 编译说明

本文档说明如何在 Windows 上从源码编译 Flux。

---

## 1. 环境要求

| 组件 | 版本要求 | 说明 |
|------|----------|------|
| Windows | 10 / 11（x64） | 开发机实测 Windows 11 Build 26100 |
| .NET SDK | **10.0** 或更高 | 含 `dotnet` CLI。用 `dotnet --list-sdks` 确认 |
| 7-Zip | 21.07+ | 运行/测试解压需要；编译本身不需要 |
| Inno Setup | 6.x | **仅打安装包时需要**，编译 EXE 不需要 |

### 检查 .NET SDK

```bash
dotnet --list-sdks
# 期望输出类似：10.0.401 [C:\Program Files\dotnet\sdk]
```

若没有 SDK（只有 Runtime），到 https://dotnet.microsoft.com/download 安装 .NET SDK 10。

## 5. 发布自包含单文件 EXE

```bash
cd src/Flux
dotnet publish -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true \
  -p:IncludeNativeLibrariesForSelfExtract=true \
  -p:PublishReadyToRun=true \
  -o ./publish
```

产物：`src/Flux/publish/Flux.exe`

| 参数 | 作用 |
|------|------|
| `--self-contained true` | 内置 .NET 运行时，目标机无需装 .NET |
| `PublishSingleFile=true` | 合并为单个 EXE |
| `IncludeNativeLibrariesForSelfExtract=true` | 原生库也打进单文件 |
| `PublishReadyToRun=true` | 预编译，启动更快（体积略大） |

> **体积换速度**：带 ReadyToRun 约 147 MB，不带约 62 MB。
> 若在意体积，去掉 `-p:PublishReadyToRun=true` 重发即可。

## 6.4 应用图标（Assets/Flux.ico）

### 图标是怎么接进去的

| 位置 | 配置 | 作用 |
|------|------|------|
| 任务栏 / 文件资源管理器 / 快捷方式 | `Flux.csproj` → `<ApplicationIcon>Assets\Flux.ico</ApplicationIcon>` | 编译时写入 EXE 的 `RT_GROUP_ICON` |
| 窗口标题栏（含所有对话框） | `Styles/Theme.xaml` → `<Style TargetType="Window">` 里设 `Icon` | 全局样式，一处生效 |
| 安装程序本体 | `Flux.iss` → `SetupIconFile=..\dist\Flux\Flux.ico` | 安装向导左上角图标 |
| 开始菜单 / 桌面快捷方式 | `Flux.iss` → `[Icons]` 里的 `IconFilename` | 快捷方式图标 |
| 右键菜单项 | `Flux.iss` → `[Registry]` 的 `Icon` 值 = `"{app}\Flux.exe",0` | 复用 EXE 内第 0 号图标 |

### 从 PNG 生成多尺寸 ICO

Windows 不同位置会请求不同尺寸（16 用于列表视图、32 用于任务栏、256 用于大图标预览）。
**只做一个尺寸会导致小尺寸被粗暴缩放、发虚**，必须打成一个多尺寸 ICO。

```python
from PIL import Image
im = Image.open("源图.png").convert("RGBA")

# 非正方形先居中裁切
w, h = im.size
s = min(w, h)
im = im.crop(((w-s)//2, (h-s)//2, (w-s)//2+s, (h-s)//2+s))

sizes = [256, 128, 64, 48, 32, 24, 16]
imgs = [im.resize((n, n), Image.LANCZOS) for n in sizes]
imgs[0].save("Flux.ico", format="ICO", sizes=[(n, n) for n in sizes])
```

### 校验 ICO 内嵌尺寸

```bash
python -c "from PIL import Image; print(sorted(Image.open('Flux.ico').ico.sizes()))"
# 期望：[(16,16),(24,24),(32,32),(48,48),(64,64),(128,128),(256,256)]
```

### 校验 EXE 里真的写进去了

用 `kernel32.EnumResourceNamesW` 枚举资源表，期望 **RT_ICON = 7 个**、**RT_GROUP_ICON = 1 个**
（7 个尺寸各一条 RT_ICON，1 条分组记录）：

```python
import ctypes, ctypes.wintypes as w
k32 = ctypes.WinDLL("kernel32", use_last_error=True)
k32.LoadLibraryExW.restype = ctypes.c_void_p
k32.LoadLibraryExW.argtypes = [w.LPCWSTR, ctypes.c_void_p, w.DWORD]
k32.EnumResourceNamesW.argtypes = [ctypes.c_void_p, w.LPCWSTR, ctypes.c_void_p, ctypes.c_void_p]
k32.EnumResourceNamesW.restype = w.BOOL
h = k32.LoadLibraryExW(r"...\Flux.exe", None, 0x2)  # LOAD_LIBRARY_AS_DATAFILE
CB = ctypes.WINFUNCTYPE(w.BOOL, ctypes.c_void_p, ctypes.c_void_p, ctypes.c_void_p, ctypes.c_void_p)
for rt, label in [(3, "RT_ICON"), (14, "RT_GROUP_ICON")]:
    found = []
    cb = CB(lambda a, b, c, d: (found.append(c), True)[1])
    k32.EnumResourceNamesW(h, ctypes.cast(rt, w.LPCWSTR), cb, None)
    print(label, len(found))
```

> **注意**：`dotnet build` 产出的 EXE（`bin/Release/...`）与 `dotnet publish` 产出的单文件 EXE
> 各自都带图标，**改完图标两处都要重新生成**，`dist/` 里也要同步 cp 一次。

## 7. 编译时踩过的坑（开发者备忘）

以下是本项目开发中实际遇到并已修复的问题，二次开发时注意：

### 7.1 WPF 绑定到只读属性会崩溃

**症状**：窗口创建时抛 `XamlParseException`，应用直接退出，日志里只有半截记录。

**原因**：`ProgressBar.Value` 的绑定默认是 `TwoWay`，而 `TaskItem.Progress` 是只读属性。

**修复**：所有绑定到只读属性处必须显式写 `Mode=OneWay`。

```xml
<ProgressBar Value="{Binding Progress, Mode=OneWay}" ... />
```

> 排查技巧：在 `App.xaml.cs` 里挂 `DispatcherUnhandledException` + `AppDomain.UnhandledException` 写日志，
> 否则 WPF 崩溃会**静默**，看起来像"卡死"。

### 7.2 7-Zip 参数里 `--` 的位置

`--` 表示"其后全部是文件名"，因此 **所有开关必须放在 `--` 之前**：

```bash
# 正确
7z x -o<dir> -y -bsp1 -bso0 -bse1 -aos -p -- <压缩包路径>

# 错误（-o 会被当成文件名，静默无输出）
7z x -- <压缩包路径> -o<dir>
```

### 7.3 无控制台进程调用 7-Zip 必须重定向 stdin

GUI 进程（WinExe）没有控制台。若不重定向 stdin，7-Zip 在需要交互输入时
会尝试打开 `CONIN$` 并永久阻塞。

**修复**：`RedirectStandardInput = true`，启动后立即 `StandardInput.Close()`。

### 7.4 日志脱敏正则不要误伤路径

`-p` 打码正则必须要求 `-p` 是**独立参数**（前面是行首/空白/引号），
否则路径中的 `gh-probe` 会被误打成 `gh-p***`：

```csharp
(?<=^|[\s""'])-p(?!\*)[^\s""]+
```

### 7.5 不要混用 `BeginOutputReadLine` 与 `WaitForExitAsync`

在特定场景下（同一进程内多次调用）`WaitForExitAsync` 可能一直等待
stdout/stderr 管道 EOF 而不返回。本项目改为：
- 独立线程同步 `ReadLine()` 读取
- 独立线程轮询 `Process.GetProcessById(pid)` 判断存活
- 加 10 分钟硬超时兜底

### 7.6 只读文件头会漏掉"尾部附加压缩包"

**症状**：`xxx.mp4` 检测结果永远是"MP4 / 普通视频文件，跳过处理"，
但用 7-Zip 直接打开却能看到内容。

**原因**：只读了文件头 64KB。网盘绕审核的分发手法是——
前面放一段**真 MP4**（头部魔数合法），把 ZIP 数据整个拼到**文件尾**。
真正的 ZIP 中央目录结束记录（EOCD）在文件末尾，头部扫描根本看不到。

**修复**：`FileTypeDetector` 增加尾部扫描（`ReadTail` + `TryDetectAppendedArchive`）。
头部判定为视频且文件 ≥ 256KB 时，再读文件尾 128KB：

1. 倒序找 EOCD `PK\x05\x06`（ZIP 规范限定在最后 65557 字节内），
   校验 `中央目录大小 > 0`；
2. 尾部 1MB 内找局部文件头 `PK\x03\x04`（兼容不写 EOCD 偏移的打包器）；
3. 尾部 1MB 内找 `Rar!\x1A\x07` / `7z\xBC\xAF\x27\x1C`。

命中则改判为压缩格式，置 `IsEmbeddedArchive = true`，**不再走"跳过"分支**。

> 注意：这是"改判"，不是"新增格式"。真视频（尾部无压缩包）仍必须判为视频并跳过——
> 反向用例见测试组 3b 的"对照"项。

### 7.7 任务对象被重新 `new` 导致 UI 卡片永不刷新

**症状**：拖入文件后，卡片各项显示 `-`、状态停在"等待处理"，
点"全部解压"弹"没有待解压的压缩包"——但日志显示处理明明成功了。

**原因**：`ProcessAsync(IEnumerable<string> filePaths, ...)` 内部
`new ExtractionTask { ... }` 重新创建了一批任务对象。
UI 的 `TaskItem` 通过**引用**持有 `ExtractionTask`，回调里靠
`ReferenceEquals(item.Model, task)` 定位卡片 → 永远匹配不上 → `Refresh()` 从不执行。

**修复**：新增 `ProcessAsync(IReadOnlyList<ExtractionTask> tasks, ...)` 重载，
UI 必须调用这个重载并传入已有的 `ExtractionTask` 对象。

> 判据：只要出现"日志正常但 UI 不动"，先查**对象身份**是否在跨层时丢失。
> 回归测试见测试组 10b。

## 10. Windows 11 一级右键菜单（IExplorerCommand + 稀疏包）

本节是本项目技术含量最高的部分，也是**最容易做不出来**的部分。
如果你只想用程序，看完这一节可以跳过；
如果你想改右键菜单或者把它移植到别的项目，**这一节请认真读完**。

### 10.1 为什么必须用稀疏包

Windows 11 的紧凑右键菜单（右键直接可见的那个）**只接受具有包标识
（Package Identity）的应用注册的命令**。传统注册表方式
（`HKCR\*\shell\...` 或 `shellex\ContextMenuHandlers`）
一定会被折叠进「显示更多选项」。

所以传统 Win32 程序要进一级菜单，唯一办法是**给它套一个稀疏包**
（Sparse Package，微软叫 "packaging with external location"）：
包里只放清单和图标，真正的 exe / dll 留在包外，用
`uap10:AllowExternalContent=true` + `Add-AppxPackage -ExternalLocation` 指向它们。

### 10.2 三层架构

```
explorer.exe
   │  ① 读 SR 数据库里的 FileExplorerContextMenus 注册，拿到 CLSID
   │  ② 按 CLSID 找 PackagedCom 记录
   ▼
dllhost.exe（SurrogateServer，跨进程宿主）
   │  ③ LoadLibrary 你的 DLL → DllGetClassObject → IClassFactory::CreateInstance
   ▼
你的 IExplorerCommand 对象
```

### 10.3 必须实现的 5 个接口

`IExplorerCommand` + `IEnumExplorerCommand` + **`IObjectWithSite`**
+ `IShellExtInit` + `IContextMenu`

`IObjectWithSite` 是硬性要求：shell 拿到 `IExplorerCommand` 后会立刻 QI 它，
失败就**静默丢弃整条命令**，连一个方法都不会调。

### 10.4 ★★ vtable 槽位（最易错的地方）

`IExplorerCommand` 在 `IUnknown` 之后的 8 个槽，**顺序必须逐字对齐**：

| 槽 | 方法 | 签名 |
|----|------|------|
| 3 | `GetTitle` | `(IShellItemArray*, LPWSTR*)` |
| 4 | `GetIcon` | `(IShellItemArray*, LPWSTR*)` |
| 5 | `GetToolTip` | `(IShellItemArray*, LPWSTR*)` |
| 6 | `GetCanonicalName` | `(GUID*)` |
| 7 | `GetState` | `(IShellItemArray*, **BOOL fOkToBeSlow**, EXPCMDSTATE*)` |
| 8 | **`Invoke`** | `(IShellItemArray*, IBindCtx*)` |
| 9 | **`GetFlags`** | `(EXPCMDFLAGS*)` |
| 10 | `EnumSubCommands` | `(IEnumExplorerCommand**)` |

**两个致命点**：

1. **`GetState` 是三个参数**，不是两个。
   写成两个的话，shell 传进来的 `&state` 会被你当成 `fOkToBeSlow`，
   而 `fOkToBeSlow = TRUE(1)` 会被当成指针写入**地址 1** → dllhost 访问冲突崩溃
   → shell 静默丢弃整条命令。
2. **`Invoke` 在 `GetFlags` 前面**（槽 8 在槽 9）。
   写反了参数就错位，同样是调用即崩。

> 这两个 bug 的共同特征：**崩溃发生在写入非法地址的瞬间，日志来不及刷**，
> 表现就是 trace 停在 `SetSite` 那一行、之后一片空白。

`GetFlags` 的选择：

- `ECF_DEFAULT (0)` → 平铺单项，直接可点（**本项目采用**）
- `ECF_HASSUBCOMMANDS (1)` → 折叠成 `⟩` 子菜单，
  但 `EnumSubCommands` 必须返回正确的 `IEnumExplorerCommand`，
  否则菜单永远卡在「正在加载…」

`GetState` 必须容忍 `psiItemArray == NULL`：一级菜单在未确定选中项时会用
NULL 调它来决定是否收录该命令，此时**必须返回 `ECS_ENABLED`**。

### 10.5 ★ 绝不要写 Classes\CLSID 注册

```reg
; 千万不要创建这个键
HKLM\SOFTWARE\Classes\CLSID\{<你的 CLSID>}\InProcServer32
```

一旦存在，shell 会走经典"进程内加载"路径、**忽略 PackagedCom**。
表现极具迷惑性：**Shift+右键的经典菜单里能看见，一级菜单里永远没有**。

对照事实：QQ 的 `{CC19E147-...}`、WinRAR 的 `{B41DB860-...}` 在
`Classes\CLSID` 下**都没有有效的 InProcServer32**，而它们的一级菜单都正常。

`ShellRegistrar.CleanClassicClsid()` 会在注册前主动清理这个键。

### 10.6 证书是硬性前提

稀疏包（.msix）必须由**受信任证书**签名，否则 `Add-AppxPackage`
报 `0x800B0109`（证书链终止于不受信任的根）。

实测结论：

- 证书在 **`LocalMachine\TrustedPeople`** 就够，**不需要** Root。
  自签证书装进 Root 等于让它成为全系统根 CA，权限过大；
  TrustedPeople 正是"信任某个具体发布者"的正确位置。
- 把证书从所有存储里删干净后再注册 → **直接失败**，这一步不能省。

### 10.7 构建流程

```bash
# 1) 生成自签证书（密码走环境变量，脚本里不留明文）
export FLUX_CERT_PASSWORD='你的密码'
bash _make_cert.sh

# 2) 编译 Shell 扩展（NativeAOT）
bash _publish_shellext.sh
#    产物：src/Flux.ShellExt/bin/Release/net10.0-windows/win-x64/publish/Flux.ShellExt.dll

# 3) 打包 + 签名稀疏包
bash _pack_shellext.sh
#    产物：dist/_pkg/Flux.ShellIntegration.msix

# 4) 编译主程序，把产物与上面两个文件凑进 dist/Flux/
dotnet publish src/SmartUnzip -c Release -r win-x64 --self-contained true \
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o _pub

# 5) 编译安装包
cd installer && "<Inno Setup 目录>\ISCC.exe" Flux.iss
```

> **注意**：改 `AssemblyName` 会牵连一串文件名
> （`Flux.exe` / `Flux.ShellExt.dll` / `Flux.ShellIntegration.msix` /
> `Flux-Sparse.cer` / `Flux.ico`，以及 `ShellRegistrar` 的常量、
> `AppxManifest` 的 `Executable` 与 `com:Class/@Path`、`_pack_shellext.sh`
> 的 PFX 与输出名、`Flux.iss` 的 `[Files]`）。
> **漏一个就装完不工作。**

### 10.8 验证：菜单不出现时怎么排查

在 DLL 里写一行日志（追加到 `%TEMP%\Flux.ShellExt.log`），
记录 `DllGetClassObject` / 每次 `QueryInterface(iid)` / `SetSite` /
`GetTitle` / `GetState` / `GetFlags`，然后按下表对号入座：

| trace 现象 | 结论 |
|---|---|
| **完全空白** | shell 从未加载 DLL → 包/CLSID 问题，或被 `Classes\CLSID` 劫持 |
| `DllGetClassObject` → QI(IExplorerCommand)=S_OK → 之后停手 | 缺 `IObjectWithSite` |
| `SetSite` 被调后彻底停 | **vtable 槽位/参数签名错**（调用即崩，故无后续日志） |
| 菜单出现但显示「正在加载…」 | `GetFlags=ECF_HASSUBCOMMANDS` 但枚举器有缺陷 → 改 `ECF_DEFAULT` |
| 一切正常但菜单里没有 | 重启 explorer；仍无则确认系统 build ≥ 22000 |

**对照实验法（最强力，建议第一个用）**：把一个**已知能正常工作的第三方包**
（WinRAR.ShellExtension、QQExtension 等）拿来对照，用 `makeappx` + `signtool`
自签后装上。若它的 DLL 能让条目出现 → 包框架、证书、部署全部正常，
问题 100% 在你的 DLL 实现。

### 10.9 换机器后还能显示吗

能。前提是走安装包（它会自动导入证书 + 注册稀疏包），
且装完后**重启一次资源管理器**（shell 会缓存扩展注册表）。
自签证书有效期默认一年，过期后同一份安装包会失效，需重新签发。
